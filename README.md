# SancireAI — Интеллектуальный помощник по регламентам и документам ДОУ

> **Кейс Центр документационного обеспечения Банка России (ЦДОБР)**  
> Разработка прототипа интеллектуального ассистента для работы с нормативными требованиями, генерации модульных документов и аудита в формате диалога.

## 📖 О проекте

Порядок работы с документами в Банке России регулируется подробными внутренними регламентами и инструкциями. Из-за специфики нормативного языка сотрудникам часто сложно быстро найти нужный пункт, определить корректный порядок визирования и составить проект приказа или распоряжения без ошибок.

**SancireAI** — это полностью локальная (On-premise) система, помогающая сотрудникам:
1. Задавать вопросы на естественном языке и получать **обоснованные ответы с точными ссылками на пункты и регламенты**.
2. В интерактивном диалоге (пошаговом мастере) собирать параметры и **автоматически формировать готовые файлы приказов `.docx`**.
3. **Аудировать черновики документов** на соответствие матрице визирования и регламентам ДОУ.
4. **Управлять версионностью регламентов** через панель администратора: загружать новые редакции, отправлять на модерацию, автоматически переводить устаревшие документы в архив и мгновенно обновлять векторный поисковый индекс.

## 🌟 Ключевые возможности

### 1. Гибридный RAG без галлюцинаций
- **Векторный поиск + лексическое сопоставление**: быстрый и точный поиск релевантных фрагментов в Qdrant с использованием эмбеддингов `qwen3-embedding:0.6b`.
- **Локальная языковая модель**: генерация ответов на базе `qwen3.5:4b` через Ollama.
- **Обязательное цитирование**: каждый ИИ-ответ строго подкреплён интерактивными ссылками на источники `{{s:id}}` с указанием документа, статьи/пункта и процента релевантности.
- **Честный откат (Fallback)**: если в регламентах нет точного ответа, система открыто сообщает об этом и не выдумывает несуществующие правила.

### 2. Мастер модульных документов (.docx)
- Пошаговый сбор реквизитов (наименование ИС, ответственные, сроки, грифы и основания) прямо в чате или в специализированном конструкторе.
- Поддержка 7 утверждённых типов документов Банка России:
  - `M01`: Приказ о вводе информационной системы в эксплуатацию
  - `M02`: Приказ о назначении ответственных за делопроизводство
  - `M03`: Акт приёма-передачи дел и материальных ценностей
  - `M04`: Приказ об утверждении локального нормативного акта
  - `M05`: Программа аудита внутренних процессов
  - `M06`: Положение о проектном комитете
  - `M07`: Распоряжение о создании рабочей группы
- Генерация валидных бинарных файлов `.docx`, строго соответствующих эталонным шаблонам.

### 3. Автоматический аудит проектов документов
- Загрузка проекта документа (`.docx` или текст) на проверку.
- Анализ по ключевым критериям: обязательные реквизиты, корректность структуры, правила матрицы визирования, проверка сроков и формулировок.
- Выдача подробного отчёта с чеклистом замечаний и рекомендациями по исправлению.

### 4. Панель ДОУ и версионность базы знаний
- Загрузка регламентов в форматах PDF, DOCX, TXT, Markdown.
- Автоматическая нарезка на смысловые фрагменты (чанкинг) и сохранение в статус «На модерации».
- Жизненный цикл документов: **На модерации ➔ Активен ➔ В архиве**.
- При активации новой редакции предыдущая версия регламента автоматически отправляется в архив, гарантируя актуальность выдаваемых норм.
- Векторизация и обновление индекса Qdrant на лету.

### 5. Безопасность и On-premise архитектура
- Все вычисления, хранение данных и генерация происходят **строго внутри локального контура** — данные не передаются во внешние облачные сервисы.
- Разграничение прав доступа (RBAC): роли `admin` (Администратор ДОУ) и `employee` (Сотрудник).
- Аутентификация на базе JWT с защищённой ротацией ключей.

## 📦 Что скачать, куда закидывать и где что генерируется

Чтобы проект оставался чистым и безопасным, большие файлы моделей, временные базы данных, кэши и конфиденциальные материалы **не хранятся в репозитории**:

### 1. Языковые модели и эмбеддинги (Скачать через Ollama)
Для работы ИИ-ответов и векторного поиска требуются две легковесные открытые модели:
```bash
ollama serve                       # Запустить службу Ollama
ollama pull qwen3.5:4b             # Модель генерации ответов (LLM)
ollama pull qwen3-embedding:0.6b   # Модель векторных представлений (Embeddings)
```
Они скачиваются стандартными средствами Ollama в системный кэш `~/.ollama`.

### 2. Векторная база данных Qdrant
Запускается локально через Docker или отдельный бинарник:
```bash
docker run -d --name qdrant -p 6333:6333 qdrant/qdrant
```

### 3. Материалы кейса и файлы регламентов Банка России
- Файл задания **`Кейс_Банка_России_ЦДОБР.pdf`** и любые локальные PDF-файлы добавлены в `.gitignore` и исключены из репозитория.
- **Куда загружать новые регламенты**: загрузка документов производится непосредственно через веб-интерфейс в разделе **«Панель ДОУ» ➔ «Регламенты»** (поддерживаются форматы PDF, DOCX, TXT, MD).
- Сервер автоматически сохраняет загруженные регламенты в директорию `sancire-backend/data/`, нарезает их на фрагменты и после модерации индексирует в Qdrant.

### 4. Директория данных и SQLite (`sancire-backend/data/`)
- Файл базы данных SQLite (`sancire.db`, `-wal`, `-shm`), пользовательские загрузки и сгенерированные файлы создаются сервером автоматически в папке `sancire-backend/data/`.
- В репозитории зафиксирован только файл `.gitkeep`. Сама рабочая база исключена из гита, чтобы избежать конфликтов и утечки данных.

### 5. Шаблоны документов (`sancire-backend/templates/`)
- В репозитории уже присутствуют утверждённые эталонные файлы `m01_*.docx` ... `m07_*.docx` и `checksums.sha256`.
- Они используются движком генерации и аудитором. Изменять их вручную не требуется.

## 🚀 Быстрый запуск

### Предварительные требования
- **Go** ≥ 1.26
- **Node.js** ≥ 20 (или Bun)
- **Ollama** с загруженными моделями `qwen3.5:4b` и `qwen3-embedding:0.6b`
- **Qdrant** (порт 6333)

### Шаг 1. Запуск Qdrant и Ollama
```bash
# 1. Запустить Qdrant
docker run -d --name qdrant -p 6333:6333 qdrant/qdrant

# 2. Проверить доступность моделей в Ollama
ollama list
```

### Шаг 2. Первичная индексация корпуса (однократно)
```bash
cd sancire-backend
go run ./cmd/qdrantload
```
*Утилита прочитает `corpus/all_chunks.json`, вычислит эмбеддинги и загрузит коллекцию `dou_knowledge` в Qdrant.*

### Шаг 3. Запуск бэкенда (Go)
```bash
cd sancire-backend
export SANCIRE_JWT_SECRET="любой-длинный-секретный-ключ-для-jwt"
go run ./cmd/server
```
*Сервер запустится на `http://localhost:8080`.*

### Шаг 4. Запуск фронтенда (React + Vite)
```bash
cd sancire-frontend
npm install
npm run dev
```
*Интерфейс откроется по адресу `http://localhost:5173`.*
