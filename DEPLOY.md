# SancireAI — инструкция по развёртыванию

Приложение генерирует модульные документы `.docx`, ведёт диалог с интерактивным сбором
параметров, аудирует проекты документов и отвечает на вопросы по регламентам ДОУ.

**Стек:** Go (бэкенд) + React/Vite (фронтенд) + Ollama (LLM) + Qdrant (векторный поиск).

```
┌────────────┐   /api/**    ┌──────────────────┐    :11434     ┌─────────┐
│  Браузер   │ ───────────► │  Go :8080        │ ────────────► │ Ollama  │
│  Vite :5173│  (прокси)    │  chat · wizard   │    :6333      │ Qdrant  │
└────────────┘              │  audit · admin   │ ────────────► └─────────┘
                            └──────────────────┘
```

---

## 1. Требования

| Компонент | Версия | Проверка |
|---|---|---|
| Go | ≥ 1.26 | `go version` |
| Node.js | ≥ 20 | `node -v` |
| Ollama (локально) | последняя | `ollama -v` |
| Qdrant (локально или Docker) | любая свежая | `curl http://localhost:6333/healthz` |

> Вся инфраструктура запускается **на одной машине с браузером** — по умолчанию Ollama и
> Qdrant слушают только `localhost`. Внешним пользователям серверы не выдаются.

---

## 2. Модели Ollama

```bash
ollama serve                       # если Ollama не запущен как служба
ollama pull qwen3.5:4b             # генерация текста (SANCIRE_LLM_MODEL)
ollama pull qwen3-embedding:0.6b   # эмбеддинги для Qdrant (SANCIRE_EMBED_MODEL)
ollama list                        # обе модели должны присутствовать
```

Имена моделей и адрес `http://localhost:11434` совпадают с дефолтами конфига —
**дополнительная настройка не нужна**, если вы ничего не меняли.

---

## 3. Qdrant

Вариант A — Docker:

```bash
docker run -d --name qdrant -p 6333:6333 qdrant/qdrant
curl http://localhost:6333/healthz   # {"status":"ok"}
```

Вариант B — бинарник: запустите `./qdrant` (порт по умолчанию 6333).

Коллекция `dou_knowledge` создаётся **автоматически** при первой индексации (см. п. 5)
или при первой активации загруженного регламента.

## 4. Бэкенд (Go)

```bash
cd sancire-backend
go run ./cmd/server          # или: go build -o sancire-server ./cmd/server && ./sancire-server
```

Лог старта:

```
INF RAG Engine ready ollama=http://localhost:11434 qdrant=http://localhost:6333
INF SancireAI Backend listening successfully addr=:8080
```

Проверка: `curl http://localhost:8080/api/health` → JSON с текущими адресами Ollama/Qdrant.

Полезные эндпоинты для диагностики:

* `GET /api/health` — адреса Ollama/Qdrant и версия сервиса;
* `GET /api/modules` — каталог модульных документов (форма конструктора строится из него, поэтому фронтенд и генератор `.docx` не могут разойтись);
* `GET /api/admin/stats` (роль `DOU_Admin`) — живые цифры для панели администратора: число фрагментов в локальном индексе, состояние коллекции Qdrant (`points`, `dimension`), модели Ollama и количество регламентов по статусам.

### Переменные окружения (все опциональны — дефолты подобраны под локальный стек)

| Переменная | Дефолт | Назначение |
|---|---|---|
| `SANCIRE_ADDR` | `:8080` | адрес Go-сервера |
| `SANCIRE_OLLAMA_URL` | `http://localhost:11434` | Ollama |
| `SANCIRE_LLM_MODEL` | `qwen3.5:4b` | генерация ответов |
| `SANCIRE_EMBED_MODEL` | `qwen3-embedding:0.6b` | эмбеддинги |
| `SANCIRE_QDRANT_URL` | `http://localhost:6333` | Qdrant |
| `SANCIRE_QDRANT_COLLECTION` | `dou_knowledge` | коллекция векторов |
| `SANCIRE_MIN_SCORE` | `0.45` | порог схожести векторного поиска |
| `SANCIRE_DATA_DIR` | `./data` | файлы (загруженные регламенты, артефакты) |
| `SANCIRE_DB_PATH` | `<SANCIRE_DATA_DIR>/sancire.db` | SQLite; по умолчанию выводится из `SANCIRE_DATA_DIR` |
| `SANCIRE_TEMPLATES_DIR` | `./templates` | бинарные шаблоны `.docx` (не редактировать!) |
| `SANCIRE_CORPUS_DIR` | `./corpus` | корпус знаний (`all_chunks.json`, `documents.json`) |
| `SANCIRE_JWT_SECRET` | генерируется | **рекомендуется задать** постоянный ключ, иначе сессии слетают при перезапуске |
| `SANCIRE_TOKEN_TTL` | `24h` | время жизни JWT (формат Go duration: `30m`, `12h`, `72h`) |
| `SANCIRE_CORS_ORIGINS` | `http://localhost:3000`, `:5173` | origins через запятую, которым разрешены credentialed-запросы |

Пример с заданием секрета (PowerShell):

```powershell
$env:SANCIRE_JWT_SECRET = "замените-на-длинный-строковый-ключ"
go run ./cmd/server
```

Bash:

```bash
SANCIRE_JWT_SECRET="замените-на-длинный-строковый-ключ" go run ./cmd/server
```

### Индексация корпуса в Qdrant

Один раз после развёртывания (и после каждого обновления корпуса):

```bash
cd sancire-backend
go run ./cmd/qdrantload            # весь корпус
go run ./cmd/qdrantload -limit 5000
```

Коды выхода: `0` — ок; `2` — Qdrant недоступен; `3` — Ollama недоступен (эмбеддинги).
Загрузка идемпотентна (детерминированные id точек) — повторный запуск безопасен.

## 5. Фронтенд (React)

### Разработка

```bash
cd sancire-frontend
npm install
npm run dev            # http://localhost:5173, прокси /api → http://127.0.0.1:8080
```

Прокси настраивается в `vite.config.ts` (`VITE_API_TARGET`, по умолчанию `http://127.0.0.1:8080`).

### Продакшен

```bash
cd sancire-frontend
npm run build          # результат в dist/
```

Раздача через nginx (пример):

```nginx
server {
    listen 80;
    server_name sancire.example.local;
    root /srv/sancire/dist;
    index index.html;

    location / {
        try_files $uri /index.html;          # SPA-роутинг
    }
    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_buffering off;                 # важно для SSE-стриминга чата
        proxy_read_timeout 120s;
    }
}
```

## 6. Регламенты: загрузка, активация, архив

1. Войдите в **Панель ДОУ** (кнопка профиля в сайдбаре → «Панель ДОУ»).
2. Секция **«Регламенты»**: выберите файл (PDF/DOCX/TXT/MD), укажите название и вид
   (Инструкция / Матрица визирования / Методические рекомендации / Другое) → «Загрузить».
   Файл нарезается на фрагменты и попадает в статус **«На модерации»** — в ответы он ещё
   НЕ подмешивается.
3. **«Сделать активным»** — текст попадает в базу знаний и в Qdrant; на вид (внутри вида)
   активной остаётся только одна редакция, предыдущая автоматически уходит в архив.
4. **«В архив»** — регламент исчезает из ответов; при желании его можно вернуть кнопкой
   активации. «Удалить» убирает файл и фрагменты из индекса.

Активные регламенты участвуют в лексическом и векторном поиске и — при доступной Ollama —
в генерации ИИ-ответов.

## 7. Как понять, что «ИИ» включён

| Сигнал | Значение |
|---|---|
| Метка ответа в чате: **«ИИ-ответ»** (`intent: answer.ai`) | Ответ сгенерирован моделью строго по найденным фрагментам с цитатами |
| Метка **«Ответ по материалам»** (`intent: answer`) | Детерминированный композер (норма найдена в текстах) |
| `curl /api/health` + логи без `WRN` про Ollama/Qdrant | Сервисы видны |
| `WRN qdrant: regulation push failed … qdrant unavailable` | Qdrant не запущен: ИИ-ответы не пострадают (лексика), но векторный поиск и пуш регламентов не работают |

Гарантии безопасности ответов:

* ИИ отвечает **только** по извлечённым фрагментам, каждый ответ обязан содержать
  допустимую ссылку `{{s:id}}` — иначе ответ отклоняется, и включается детерминированный
  композер.
* Мастер-конструктор документов, аудитор, приветствие и отказы **всегда** детерминированы —
  модель их не подменяет.
* Если однозначного ответа в материалах нет — приложение честно пишет об этом
  и не выдумывает.

## 8. Проверка после развёртывания (чек-лист)

```bash
# 1. Сервисы
curl http://localhost:11434/api/tags | grep -q qwen3.5:4b && echo LLM_OK
curl http://localhost:6333/healthz && echo QDRANT_OK
curl http://localhost:8080/api/health

# 2. Индекс корпуса (однократно)
cd sancire-backend && go run ./cmd/qdrantload && echo INDEX_OK

# 3. Фронтенд
cd sancire-frontend && npm run dev      # открыть http://localhost:5173
```

В приложении:

1. Чат: «привет» → детерминированное приветствие со списком возможностей.
2. Чат: «Какой порядок согласования проекта документа?» → ответ с карточкой источников;
   при живой Ollama — с меткой «ИИ-ответ».
3. Чат: «Приказ о вводе ИС в эксплуатацию» → мастер собирает параметры шаг за шагом,
   в конце отдаёт готовый `.docx`.
4. Панель ДОУ → Регламенты: загрузить файл → активировать → задать вопрос по нему в чате
   → ответ со ссылкой на фрагмент; «В архив» → вопрос перестаёт находиться.

## 9. Типовые проблемы

| Симптом | Причина / решение |
|---|---|
| `connection refused` на 11434 в логах | Ollama не запущен → `ollama serve` |
| Ошибки эмбеддингов при `qdrantload` | Не скачана `qwen3-embedding:0.6b` → `ollama pull …` |
| `qdrant unavailable` | Qdrant не запущен (п. 3); ответы работают, векторный поиск — нет |
| ИИ-ответов нет, хотя Ollama «работает» | Проверьте `SANCIRE_LLM_MODEL` = `ollama list`; чат честно откатывается на детерминированные ответы |
| Пустой ответ на вопрос по новому регламенту | Он в статусе «на модерации» → «Сделать активным» |
| 401/403 в Панели ДОУ | Войдите администратором: `admin` / `admin123` (**смените пароль в проде**) |
| SSE/стриминг «обрывается» за nginx | `proxy_buffering off;` (п. 5) |
| Сессии слетают после перезапуска | Задайте постоянный `SANCIRE_JWT_SECRET` |

## 10. Учётные записи по умолчанию

| Логин | Пароль | Роль |
|---|---|---|
| `admin` | `admin123` | Администратор ДОУ (Панель ДОУ, регламенты) |
| `employee` | `employee123` | Сотрудник (чат, конструктор, аудит) |

> В проде смените оба пароля и задайте `SANCIRE_JWT_SECRET`.
